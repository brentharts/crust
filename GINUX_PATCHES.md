# Ginux patches to make later

Ginux moves fast, so for now nothing in its tree is edited to suit Crust. This
file collects the places where the Ginux source, not Crust, is the sensible
thing to change, so they can be applied in one batch when the code settles.

Each entry says where the problem is, what Crust objects to, the change that
would clear it, and whether Crust is expected to grow support instead (in which
case the patch is never needed and the entry is simply deleted).

Measured with `python3 crust_port.py survey --crust ../crust --blockers`
against Crust `ginux-port-7` (13 of 71 files translate, 6 partially).

## Small, mechanical edits

These are one-line edits that do not change behaviour. Crust does not infer a
closure's parameter types when the closure is bound to a variable before it is
called, and it has no iterator protocol, so iterators held in variables fail.

| File | Line | Now | Change |
| --- | --- | --- | --- |
| `kernel/src/scheduler.rs` | 1335 | `let limit_for = \|domain\| { .. };` | `\|domain: u64\|` (annotate the parameter) |
| `kernel/src/linux_overlay.rs` | 397 | closure parameter `node` has no type | annotate it: `\|node: &Node\|` |
| `kernel/src/native_elf.rs` | 417 | `let mut matches = iter...; matches.next()?` | call `.next()` on the chain directly, or use `.find(..)` |

*Crust-side alternative:* infer closure parameter types from the first call, and
accept an iterator bound to a `let` that is only advanced with `.next()`.

## Standard-library types the units use

Crust monomorphises from source and has no `std`/`alloc`. Where a unit needs one
of these, the type has to be defined locally (or the unit left to the host
build).

| File | Line | Type | Suggested change |
| --- | --- | --- | --- |
| `kernel/src/sync.rs` | 154 | `core::mem::ManuallyDrop<T>` | a local `struct ManuallyDrop<T>(T)` with `Deref`, or Crust support |
| `kernel/src/memory.rs` | 23 | `MaybeUninit<FrameAllocator>` | the type is defined in another unit; import it, or Crust support for cross-unit generics |
| `services/network/src/registry.rs` | 647 | `String` | `alloc` only; host-side service, probably leave unported |
| `crates/oci/src/lib.rs` | 139 | `Vec<T, A>` (two type arguments) | host-side crate; leave unported, or use `Vec<T>` |
| `kernel/src/image_store.rs` | 17 | `ImageStore<A, B>` two-argument form | check whether the second parameter is a defaulted allocator |
| `services/network/src/main.rs` | 56 | `Layout::align()` | `alloc::alloc::Layout`; host-side |
| `tools/manifest-tool/src/bin/seed-benchmark-cache.rs` | 22 | `File::seek` | host tool using `std::fs`; leave unported |
| `tools/manifest-tool/src/main.rs` | 34 | `.collect()` outside a `for` | host tool; leave unported |

## Where Crust is expected to move instead

These are listed so nobody patches Ginux for them by accident. Each is a
Crust gap, tracked in the survey, not a Ginux defect:

- `as_chunks` / `as_chunks_mut` (`crypto.rs`, `protocol-state`, `linux_random.rs`)
- `windows`, `rposition`, `flat_map`, `chain` after `map` on iterators
- the `arch/x86_64/cpu/*` files (`execution.rs`, `linux_futex.rs`,
  `linux_signal.rs`, `linux_syscall.rs`): statics from the parent module now
  resolve, but they use `RuntimeRef<Banked*>` Deref wrappers whose types are
  generated by `macro_rules!` inside the 34k-line `cpu.rs`
- `asm!` operand modifiers such as `{selector:x}`
- `impl<'a, T, const N: usize> IntoIterator for &'a RuntimeRef<[T; N]>`
- string patterns in `match` (`network.rs`)
- `let ... else` with a type that cannot yet be inferred (`manifest.rs`)

## How to use this file

1. When Ginux is quiet, re-run the survey.
2. For every row above that still fails, apply the suggested edit in one commit
   titled "Ginux: changes for the Crust port".
3. Delete rows as Crust learns the construct.
